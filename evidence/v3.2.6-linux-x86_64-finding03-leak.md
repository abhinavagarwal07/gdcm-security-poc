# Finding 3 on Linux x86-64: leaked pointer reveals the library base

GDCM v3.2.6 (`9c71b163`), Ubuntu 24.04, gcc 13.3, unsanitized `-O2 -DNDEBUG`,
default PIE, stock glibc, `randomize_va_space=2`.

`DiscreteSegment` derives its end from an unchecked uint16 length, and because
`palette.size()` must equal the LUT descriptor N to reach the copy loop, N scales
how far past the element buffer the read goes. In the retained shaped run,
N=65535 completes a 131070-byte overread, the uint16 descriptor's ceiling.

Live C++ objects land in that window, and their vtable pointers are stored plain.
A recovered `gdcm::ByteValue` vtable pointer yields the load base of
libgdcmDSED.so in this build by subtracting a fixed offset:

    derived_base = leaked_pointer - 0x106208

The harness derives the base that way and uses dladdr and /proc/self/maps only as
an independent check, printed alongside. Reporting the looked-up value instead
would be circular -- any process can ask where it is loaded -- so a disagreement
is a hard failure (`ASLR_DEFEAT_NOT_ACHIEVED`, exit 6) and never falls back to
the checked value. The negative control below feeds a deliberately wrong offset
to show that failure path actually fires.

Two limits. The offset is specific to this build of libgdcmDSED.so.3.2.6,
obtained with `nm -D` plus the Itanium ABI's 0x10; an attacker against a
distribution build needs that build's offset, which is ordinary for exploitation
but should be stated rather than implied away. And the harness finds the pointer
by scanning the whole out-of-bounds window rather than reading a fixed index --
empirically the hit locations were identical across the retained runs for a
fixed input, but the harness does not assume a fixed index. This proves local
API-level disclosure when the caller applies the LUT and obtains the decoded
pixel buffer; it does not prove that a network service returns those pixels.

## Reproduction commands

```bash
CC=gcc CXX=g++ ./scripts/build-target.sh vulnerable none release
python3 generators/finding-03-leak.py \
  --out _generated/leak_shape.dcm \
  --n 65535 --shape-count 50 --shape-size 8192
sha256sum _generated/leak_shape.dcm

export LD_LIBRARY_PATH="$PWD/_build/vulnerable-none-release-gdcm/bin"
ulimit -c 0
_build/vulnerable-none-release-harness/finding03_leak \
  _generated/leak_shape.dcm

# Negative control: the one-byte-wrong offset must return 6.
_build/vulnerable-none-release-harness/finding03_leak \
  _generated/leak_shape.dcm --offset 0x106209
```
